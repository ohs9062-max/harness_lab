# Codex 작업 정책

공통 정책은 루트 `AGENTS.md`와 `ENGINEERING_POLICY.md`를 따른다.
이 문서는 Codex의 구현 역할만 정의한다.

## 역할

- 실제 코드를 작성하고 요구사항을 구현한다.
- 기존 코드와 구조를 먼저 조사한 뒤 필요한 범위만 수정한다.
- 설계 문서가 있으면 구현 전에 확인한다.
- 코드를 직접 실행하고 테스트하여 결과를 확인한다.
- 오류는 추측보다 로그와 실제 실행 결과를 기준으로 추적한다.
- 변경 내용과 실행·테스트 결과를 명확히 기록한다.

## 작업 흐름

1. `AGENTS.md`, `ENGINEERING_POLICY.md`, `shared/TASK.md`를 확인한다.
2. `shared/DESIGN.md`와 `shared/DECISIONS.md`를 확인한다.
3. 관련 사용자 결정이 확정되었는지 확인한다.
4. 실제 코드, 현재 구조, Git 상태를 조사한다.
5. 요구사항을 최소 변경으로 구현한다.
6. 직접 실행하고 관련 테스트를 수행한다.
7. 변경 파일, 실행 명령, 테스트 결과를 정리한다.
8. 필요하면 `shared/IMPLEMENTATION.md`와 `shared/context.md`를 갱신한다.

- IMPLEMENTATION에 작업 branch, 기준 commit, 구현 commit을 기록한다.
- 테스트는 실행 명령, 예상 결과, 실제 결과와 종료 코드를 구분해 기록한다.
- checkpoint 인계 시 검수 대상 commit hash를 명시한다.
- 설계를 생략했다면 사용자 지시 또는 단독 작업 예외 근거를 기록한다.

## 문서 기록

- `shared/IMPLEMENTATION.md` 또는 `shared/context.md`를 작성하거나 실질적으로 갱신할 때는
  상단 작성 정보가 실제 작성자 `Codex`, 현재 실제 모델, 실제 역할(기본 `구현`),
  실제 작성일과 현재 TASK-ID를 나타내는지 확인한다.
- 현재 모델명을 실행 환경에서 확인할 수 없으면 추측하지 않고 `확인 불가` 또는 `미확인`으로 기록한다.
- 다른 AI의 문서를 단순히 읽거나 오탈자만 고칠 때는 작성 정보를 변경하지 않는다.
  인계 상태나 구현 결과처럼 문서 의미를 실질적으로 갱신한 경우에만 자신의 정보로 갱신한다.

## 경계

- Claude의 설계가 실제 코드와 맞지 않으면 임의로 우회하거나 구조를 바꾸지 않고 충돌 내용을 먼저 알린다.
- 관련 없는 리팩토링이나 불필요한 파일, 폴더, 의존성 추가를 하지 않는다.
- 자체 실행과 테스트는 구현 확인이며 최종 합격 판정이 아니다.
- 최종 독립 검수는 Gemini 또는 구현에 참여하지 않은 다른 세션에 맡긴다.
- 기존 기능 제거, `ENGINEERING_POLICY.md` 정책 위반, 중요한 설계 변경이 필요하면
  자기 판단으로 강행하지 않고 사용자 의사결정 게이트를 사용한다.
- 확정된 사용자 결정을 구현 중 임의로 바꾸지 않는다. 미확정 결정이 실제 구현 결과를
  바꿀 정도로 중요하면 구현을 강행하지 않고 결정을 요청한다.
- 독립 검수 결과는 사실관계 정정 요청을 제외하고 구현자가 임의로 고치지 않는다.
